## 做法与结果

- **部首数据**：`chinese-xinhua` 数据集的 `radicals` 字段，覆盖 **2890/2893 字 ≈ 99.9%**（仅缺 `囱屎啰`）。
- **成族规则**：**只有人工写了讲解的部首才成族**（`MEAN` 表）。这一条自动把
  笔画类部首（`一` `丿` `十` `又` `八` `子`…）挡在门外——它们和字义无关，聚在一起是错的。
- **归属规则**：每个字按**教材首次出现**归入某一册某一族，天然消除跨册重复。
- **切块**：单族上限 12 字，超出按年级切分。

**结果：318 族 / 2033 字 / 单族 2–13 字 / 重复 0。**

| 字数 | 432 | 675 | 328 | 315 | 317 | 32 |

## 三个必须记住的坑

1. **`月` = 月亮 还是 肉（身体）？**
   `肥 肯 胡 胜 腊 脱 腻 脆 股 育` 都是**肉**，`期 朗` 才是**月**。
   字形完全相同，机器无法分辨。**整族已排除**（67 字），等人工拆成两族后再启用——
   宁可少教一族，也不能把身体部位讲成月亮。
2. **字典部首 ≠ 孩子看得出的部件。**
   `来`→木、`才`→扌、`和/古/吴`→口，这些是字典归类，但孩子看不出来。
   自动成族约有 **85% 精度**，剩余需人工过一遍。
3. **笔画类部首不成族。** 见上，已在规则层挡住。


## 3.1 IDS 拆部件：解决了「伪族」

`ids.txt` 提供**直接部件**（`江` → ⿰氵工 = `氵 + 工`；`想` → ⿱相心 = `相 + 心`），
因此可以给每个字填 `parts`，并**校验部首是否真的出现在字里**。

**成族规则升级为双条件**（缺一不可）：
1. 字典部首**就是**该族部首；
2. 该部首**确实出现在该字的可视部件中**。

这条规则剔除了 **126 个伪族归属**：

| 字 | 字典部首 | 实际部件 | 结果 |
|---|---|---|---|
| 才 | 扌 | (拆不开) | 剔除 |
| 来 | 木 | (拆不开) | 剔除 |
| 周 | 口 | (拆不开) | 剔除 |
| 火 | 火 | 八 + 人 | 剔除（**曾错入「亻族」**）|
| 肚 | 月 | 月 + 土 | 剔除（**曾错入「土族」**）|

> 这两行是血泪教训：只按「部件里碰上有讲解的部首」归族，
> 会让 `火` 因为有「人」而进人族。**必须双条件。**

另：拆不开但**本身即部首**的字（`口` `目` `日` `虫` `女` `车`…）作为**族根**收入。

**结果：301 族 / 1981 字（68.5%）。**

## 3.2 声符族自动发现（意外的大收获）

有了 `sound`（非部首的那一半部件）后，可以按声符聚类，
再用**读音相似度**过滤（复用应用里的 `pyTier` 逻辑，含舌尖元音处理），
把「又」族里 `鸡观戏汉` 这种毫不相干的噪声剔掉。

**结果：96 个声符族通过，146 个因读音不符被剔除。** 应用里最精华的「青之家族」
（原 6 字），现在有 96 个同款：

```
声符「方」7字  房 纺 坊 仿 芳 访 妨
声符「包」7字  泡 炮 抱 饱 雹 咆 袍
声符「乔」6字  桥 轿 娇 骄 侨 矫
声符「令」5字  铃 领 玲 岭 伶
声符「屯」5字  纯 炖 顿 吨 钝
```

## 3.3 🔴 拼音数据严重损坏（已修）

`_pinyin_qa.py` 拿 `pypinyin` 逐字比对，发现 **306/2893（10.6%）的拼音是错的**：

```
飞  i    -> fēi      声母整个丢了
方  āng  -> fāng
风  ng   -> fēng     只剩韵尾
备  ICP  -> bèi      抓进了网页杂讯
```

根因：cngwzj「拼音版」页把拼音拆成多个 HTML 元素，配对正则只抓到碎片。

**修复难点**：不能一刀切换成 pypinyin，因为**多音字要保留教材读音**
（`乐`=yuè 不是 lè、`长`=cháng 不是 zhǎng）。所以按规则区分：
真后缀/前后鼻音/非法音节 ⇒ 判为损坏并改用 pypinyin；
其余不一致 ⇒ 判为多音字，**保留教材读音**。

**结果：修正 301 个，保留 33 个多音字教材读音，复核剩余损坏 0。**

> 这条如果不查，`飞` 就会教成 `i` —— 正是本应用红线里
> 「识字应用最怕教错音」最不能容忍的错。

## 4.1 关键教训：**没有词频就分不出「白天」和「彻天」**

| 数据源 | 覆盖率 | 抽样（"天"的组词） | 可用？ |
|---|---|---|---|
| `chinese-xinhua` ci.json（26 万词，无词频） | 99.1% | 彻天 构天 白天 告天 垂天 瞓天 | ❌ 大量古文词/OCR噪声 |
| 同上 +「两字都是教材生字」过滤 | 98.9% | 彻天 构天 白天 告天 垂天 冰天 | ❌ 过滤不掉 |
| **jieba dict.txt（带词频）** | **98.4%**（门槛40） | **今天 一天 每天 天下 天然 天津** | ✅ |

> 词条多不代表可用。**必须用「词频」当裁判**，才能把活人说的话和故纸堆分开。

门槛扫描：`300→83.1%  150→91.6%  80→96.2%  60→97.4%  40→98.4%  20→99.0%`，
取 **40**（`浮萍`51 `瓢虫`73 `蜻蜓`114 这类好词刚好进得来）。

# 第五阶段：转成应用原生格式并接入（`data/expand.js`）

**上面这个设计问题已经定了：分开放。**「精选」= 手写 5 族，各年级 = 自动生成。

## 5.1 为什么要"转格式"而不是"改应用"

应用的自带质检（`app.js` 的 `validatePacks`）对每条数据有硬要求：
`scene` / `emoji` / `parts` / `notes` / `q3` / `q4` 一个都不能少，
非根字的 `parts` 必须正好 2 个、`notes` 必须正好 2 条，`q3` 答案必须是图片选项，
`q4` 的答案必须正好是本字……

`data/families.js`（聚合结构）和 `data/questions.js`（题库）都**不满足**这些约束。
`_expand.py` 的职责就是把「聚合结构 + 题库」**编译**成应用能直接吃的字族格式：

```
families.js (301 族)  ─┐
questions.js (2877 字) ─┼─►  _expand.py  ─►  data/expand.js (290 族 / 1824 字)
ids 表 (部件分解)      ─┘
```

**成果：不用改一行应用代码，就把 1-6 年级接进去了。**

## 5.2 两个必须记住的坑

### 坑一：义符不一定在第一位（`⿱化贝` 的顺序问题）

IDS 给的部件顺序是**视觉顺序**（`货` = `⿱化贝` → 上、下）。
但应用约定 `parts[0]` 是**义符**、`parts[1]` 是**声符**。

`货` 的义符是 `贝`（钱财），声符是 `化`——和视觉顺序相反。
照 IDS 顺序直接输出，界面上就会讲**"上面「化」表示意思"**，这是错的。

**修法**：算出哪个部件是本族部首，把它排到 `parts[0]`，位置词按它**真实的位置**说
（"下面「贝」表示意思"）。校验放在 `tools/verify-merged.js`，
因为它懂**全形↔变形**的对应（`人`↔`亻`、`水`↔`氵`），不会像应用质检那样误报。

> 试过把族的 `shapePart` 声明给应用、让它强制校验，结果报出 88 条误判
> （`会`=`人+云` 却要求义符是 `亻`）。**不变量要放在懂它的工具里，而不是最省事的工具里。**

### 坑二：声符不一定是教材生字

判断"能不能说提示读音"要查声符的拼音，但声符经常本身不是生字
（`兆`、`乔`、`曷`、`隹`……），在题库里查不到 → 只能保守说"记字形"，
而应用内置的部件读音表知道它们 → 反过来报"应当说提示读音"。

**修法**：查不到时用 `pypinyin` 补齐。修完自检从 14 个问题降到 0。

## 5.3 验证工具链（这一阶段新加的，后来者务必用）

数据错误靠肉眼看 1824 个字是看不出来的。三个工具：

| 工具 | 查什么 |
|---|---|
| `tools/verify-merged.js` | **离线**模拟应用初始化：族数/字数、逐条套用应用质检规则、红线专项、义符位置、组内重名 |
| `tools/browser-test.js` | **真浏览器**端到端：CDP 驱动 headless Chrome，真的点按钮走完一轮会话，捕获运行时报错，并读应用自检结果 |
| `tools/build-single.py` | 由 `index.html + style.css + data/*.js + app.js` 重建单文件版，**别再手工拼** |

```bash
python tools/wordlist-pipeline/_expand.py   # 生成 expand.js
python tools/build-single.py                # 重建单文件版
node tools/verify-merged.js                 # 离线校验
node tools/browser-test.js                  # 真浏览器校验（需先起 http 服务）
```

### 为什么必须有 `browser-test.js`

`verify-merged.js` 是**照着我自己的理解**写的，我理解错的地方它也查不出来
（比如"义符在 parts[0]"这条，我的离线校验器一开始就是错的）。
只有真浏览器里跑一遍，才能发现：**"上面「化」表示意思"** 这种
"数据完全合规、但内容是错的"问题。

**一句话：离线校验查"数据合不合规"，浏览器校验查"孩子看到的是不是对的"。**
